# Rewind

Rewind — приложение с открытым исходным кодом для записи игровых моментов на **Windows 11 x64 с NVIDIA NVENC**. Оно хранит последние секунды игры или выбранного монитора в кольцевом буфере и сохраняет клип по кнопке или глобальной горячей клавише. Также доступны обычная запись и скриншоты.

**Текущая версия: `0.1.0-beta.1` · pre-release.** Это версия готовящейся первой публичной беты; эта страница не объявляет опубликованный GitHub Release. Приложение находится в разработке, ограничения перечислены ниже.

Стек: .NET 10 / WPF, Windows Graphics Capture (WGC), DXGI, NVENC и WASAPI. FFmpeg запускается отдельным процессом. Инъекции DLL в игру, собственные драйверы и виртуальные аудиокабели не используются.

## Возможности

- Буфер Rewind от **15 до 600 секунд**, с ограничением размера видео на диске. Обычная запись может работать одновременно с Rewind.
- Захват окна игры или всего выбранного монитора. «Без жёлтой рамки» управляет рамкой WGC для окна; захват монитора без рамки использует DXGI.
- Кодеки AV1, HEVC и H.264 через NVENC. Автовыбор проверяет реальную инициализацию в порядке AV1 → HEVC → H.264; доступность зависит от GPU, драйвера и FFmpeg.
- **Save Queue:** повторные команды сохранения принимаются во время экспорта, обработка идёт по порядку, общий захват продолжается.
- Звук игры или системы, микрофон и отдельная дорожка Discord; общий Mix и отдельные дорожки в MKV. Громкость, усиление, выбор канала, проверка и прослушивание микрофона.
- Необязательное фоновое сжатие в MP4 с сохранением оригинала и всех аудиодорожек. Импорт профиля из MP4 COMPRESSOR.
- Настраиваемые глобальные хоткеи, диагностика конфликтов, трей и собственные уведомления Rewind.
- Встроенные шрифты **Rewindtica v0.1** (Bold, Medium, Light) и Inter; установка шрифтов в Windows не нужна.

## Требования и запуск

Целевая платформа — **Windows 11 x64**, видеокарта NVIDIA с поддержкой NVENC для выбранного кодека и подходящий драйвер. AV1-кодирование и AV1 NVDEC требуют соответствующих аппаратных возможностей; они есть не у всех NVIDIA GPU. Другие ОС и GPU без NVENC не заявлены как поддерживаемые.

Для запуска self-contained сборки установка .NET не нужна. Держите **всю папку сборки** вместе: рядом с `Rewind.exe` нужны библиотеки, ресурсы, notices и `tools/ffmpeg.exe` / `tools/ffprobe.exe`. Получить локальную сборку из исходников можно по инструкции ниже.

1. В настройках выберите окно игры либо автоматический выбор последнего активного приложения. Для предсказуемого результата укажите окно явно.
2. Выберите «Только игра» или «Игра + рабочий стол». Второй режим записывает **весь выбранный монитор**, включая другие окна.
3. Настройте звук, микрофон, длительность буфера и папку клипов.
4. Включите Rewind и дождитесь набора буфера. Сохраните момент кнопкой или хоткеем.
5. Закрытие окна убирает приложение в трей. Для завершения выберите **«Выход»** в меню трея; принятые сохранения будут завершены перед выходом.

## Как сохраняются клипы

Команда сохранения фиксирует своё время **до** ожидания очереди. Принятие команды ещё не означает, что файл готов: Rewind закрепляет видео и PCM в исходном временном окне, подготавливает снимок, затем экспортирует и проверяет MKV. Успешное уведомление появляется после проверенной публикации файла; миниатюра и MP4-сжатие не являются условием успеха.

В Save Queue не более **8 принятых незавершённых запросов**, включая один экспортируемый. Экспорт выполняется последовательно по FIFO; подготовка хвостов может идти независимо. После приёма кнопка сохранения освобождается, при полной очереди — временно отключается. Лимиты памяти, закреплённого видео и свободного диска могут отклонить новый запрос раньше; уже принятые задания не вытесняются.

Видео пишется примерно двухсекундными MKV-сегментами. Подготовка может ждать закрытия сегмента, содержащего момент команды; deadline — **12 секунд от момента принятия команды**, а не от начала экспорта. Это предел ожидания хвоста, а не длительность всего экспорта. Отсутствующий хвост приводит к ошибке вместо публикации усечённого момента. Общий захват при этом продолжается.

Нижняя граница клипа учитывает настроенное окно времени, начало текущей истории Rewind и **последнюю успешно опубликованную** границу сохранения (cutoff). FIFO уточняет её по результатам предыдущих запросов внутри уже закреплённого снимка. Ошибка или отмена не потребляет историю; следующий запрос может включить неудавшийся интервал в пределах собственного окна. Старое задание после смены эпохи Rewind не сдвигает новую историю. После успешного Save следующий клип содержит новую историю: например, при окне 30 секунд и следующей команде через 15 секунд — примерно 15 секунд.

Состояния различают «Подготовка клипа», «Клип в очереди» и «Сохранение клипа». Штатный выход дожидается принятых экспортов и может занять время. Save Queue удерживает PCM в памяти: аварийное завершение процесса или отключение питания не гарантирует восстановление ещё не опубликованных клипов. Точные границы, бюджеты ресурсов, отмена и диагностика — в [docs/SAVE-QUEUE.md](docs/SAVE-QUEUE.md).

### AV1 и NVDEC

При подходящих границах и совместимом AV1-битстриме используется консервативный packet-copy с проверкой пакетов, временных меток и полного декодирования результата. Он не округляет начало к предыдущему ключевому кадру. Для остальных случаев видео обрезается по доступным кадрам и перекодируется в NVENC.

На AV1-пути декодирование может использовать `av1_cuvid` / CUDA (NVDEC), если реальная проверка сегмента подтверждает поддержку. При недоступности или сбое аппаратного пути тот же закреплённый снимок обрабатывается программным декодером, без нового Save и новой временной границы. Это fallback **декодирования**; NVENC по-прежнему нужен для перекодирования. Экспериментальный Hybrid SaveClip выключен по умолчанию, пользовательского переключателя нет.

### Формат и фоновое сжатие

Основной клип — MKV с Mix первой дорожкой и доступными отдельными Game/System, Microphone, Discord. Системный звук уже содержит Discord, поэтому в Mix он повторно не добавляется. Рядом сохраняется JSON с диагностикой аудио, предупреждениями и удалёнными разрывами захвата. Тихий или неисправный микрофон сам по себе не блокирует сохранение видео.

Очередь MP4-сжатия работает отдельно от Save Queue: один процесс за раз, копия `имя.compressed.mp4`, оригинал остаётся. Отключение сжатия исключает новые задания, уже добавленные продолжаются. Его очередь хранится на диске; незавершённое сжатие возобновляется с начала после запуска. NVENC общий с записью, влияние на нагрузку возможно, уменьшение размера не гарантируется. Импорт профиля MP4 COMPRESSOR не импортирует удаление оригиналов или перезапись файлов.

## Настройки и данные

По умолчанию: 1080p60, буфер 180 секунд, CQ 27, максимум 16 Мбит/с. Клипы сохраняются в `Видео\Rewind` с группировкой по приложению. Можно выбрать другие папки клипов и временного буфера; недоступная папка буфера вызывает ошибку без скрытого возврата на диск C:. Старые файлы при смене пути автоматически не переносятся.

Для совместимости рабочие данные остаются в `%LOCALAPPDATA%\Replay`:

| Данные | Путь по умолчанию |
| --- | --- |
| Настройки | `settings.json` |
| Очередь MP4-сжатия | `compression-queue.json` |
| Ошибки | `errors.log` |
| Временный видеобуфер | `buffer\` |

В «Дополнительно» доступны лимит буфера на диске, порог тишины, сдвиг аудио и постоянно видимая секция параметров захвата. «Показывать служебную информацию» по умолчанию выключен, сохраняется и сразу скрывает нижнюю строку без пустого места; всплывающие уведомления продолжают работать. Здесь же отображается версия из метаданных сборки, включая суффикс беты.

Внутренние имена `Replay`, `src/Replay` и mutex `Local\Replay.Nvidia.Desktop` сохранены для совместимости. Одновременный запуск старой и новой сборок ограничен общим mutex.

## Сборка из исходников

Запускайте команды в PowerShell из корня репозитория на Windows. Для загрузки SDK, NuGet-пакетов и FFmpeg нужен интернет.

### Локальная сборка для разработки

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
./dist/Rewind/Rewind.exe
```

`bootstrap.ps1` устанавливает SDK **10.0.401** в `.tools/dotnet` и загружает FFmpeg essentials в `.tools/ffmpeg`; системная установка SDK не меняется. `build.ps1` выполняет Release publish для `win-x64 --self-contained true`, копирует локальные media tools и создаёт `dist/Rewind/`. Закройте экземпляр из этой папки перед повторной сборкой. Путь можно изменить через `-OutputDirectory`.

Чтобы отдельно проверить Debug и Release:

```powershell
./.tools/dotnet/dotnet.exe build src/Replay/Replay.csproj -c Debug
./.tools/dotnet/dotnet.exe build src/Replay/Replay.csproj -c Release
```

### Сборка для ручной GUI-проверки

После bootstrap дополнительно подготовьте `.tools/ffmpeg-full/ffmpeg.exe` и `ffprobe.exe` той же версии: **bootstrap не создаёт этот каталог**. Либо передайте относительный к корню репозитория путь к подготовленной паре через `-MediaDirectory`. Скрипт проверяет наличие `libdav1d`, `av1_cuvid` и `av1_nvenc`. Full-сборка нужна в том числе для анализа AV1-сегментов через libdav1d; essentials использует другой программный декодер и может давать дополнительную задержку.

```powershell
./scripts/publish-manual-test.ps1
./artifacts/rewind-manual-test/Rewind.exe
```

Скрипт собирает self-contained Release во временную папку, добавляет .NET Desktop Runtime, ресурсы, лицензии/notices и media tools, выполняет smoke-проверку и только затем заменяет итоговую папку. Он проверяет работающие экземпляры и сохраняет предыдущую сборку. Перед заменой завершите Rewind через трей. Это локальная тестовая упаковка, а не публикация GitHub Release.

SDK и NAudio.Wasapi 2.3.0 зафиксированы, но URL загрузки FFmpeg в bootstrap изменяемый, без version/hash lock: побайтовая воспроизводимость пока не обеспечена. `.tools`, `bin`, `obj`, `dist`, `publish` и `artifacts` исключены из Git. Различия комплектования notices и открытые вопросы бинарного распространения описаны в [THIRD-PARTY.md](THIRD-PARTY.md); наличие локальной сборки не закрывает их автоматически.

## Ограничения беты

- Только SDR; корректного HDR tone mapping нет. Холст 16:9, исходные пропорции сохраняются с полями.
- При сворачивании игры Windows может перестать отдавать кадры. Автоперехода с окна игры на рабочий стол нет. Защищённый контент и эксклюзивный fullscreen требуют проверки на месте.
- Автоисточник — эвристика последнего активного приложения. При активной записи источник не переключается вслед за Alt+Tab.
- При потере DXGI видео переподключается с ограниченными попытками. Завершённая Rewind-история и аудиозахват сохраняются; недоступные интервалы вырезаются из видео и аудио одинаково. Клип может быть короче настроенного окна. Активная обычная запись завершается до восстановления.
- В родном разрешении DXGI передаёт GPU-текстуры в NVENC; текущий путь масштабирования использует CPU и NV12. Нагрузка зависит от режима и оборудования.
- Временная привязка видео оценивается до кодирования, WASAPI привязан к QPC. Сдвиг аудио помогает подстроить синхронизацию, но покадровая точность для любого оборудования не гарантирована.
- Discord должен работать до начала записи. После его перезапуска или отключения аудиоустройства перезапустите буфер; автоматического аудиопереподключения нет. Устройство по умолчанию фиксируется на старте.
- Аудио Rewind хранится в ограниченном RAM-буфере. После аварии оно не восстанавливается автоматически. Незавершённые обычные записи обнаруживаются при запуске; их временные файлы сохраняются для ручного восстановления.
- Видимость оверлея и работа хоткеев в конкретной игре / эксклюзивном fullscreen требуют ручной проверки. Поддержка Forza в этих условиях не подтверждена; системные уведомления тоже могут подавляться Windows. Нижняя служебная строка по умолчанию скрыта, её можно включить в настройках.
- Автозапуска с Windows и автозаписи при запуске игры нет.
