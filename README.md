# Rewind

Приложение и файлы сборки теперь называются Rewind (`Rewind.exe`, `Rewind.dll`). Минимальная длительность буфера — 15 секунд, максимальная — 600; любое целое значение в этом диапазоне сохраняется точно. Старые значения ниже 15 при загрузке становятся 15 в памяти. Загрузка не перезаписывает `settings.json`; значения выше 600 проходят прежнюю проверку некорректной конфигурации.

Для совместимости настройки, очередь сжатия, журналы и временный буфер остаются в `%LOCALAPPDATA%\Replay`. Сохранённые пути клипов и горячие клавиши не меняются, медиафайлы не переносятся. Новые настройки используют `Видео\Rewind` для клипов. Внутренние `namespace Replay`, `src/Replay`, идентификатор манифеста `Replay.app` и mutex `Local\Replay.Nvidia.Desktop` намеренно сохранены; последний исключает одновременный запуск старой и новой сборки.

Компактная клиповалка для Windows 11 x64 и NVIDIA. .NET 10 / WPF, Windows Graphics Capture, NVENC, WASAPI. Никаких DLL в игре, драйверов или виртуальных аудиокабелей.

## Версия 0.2.6: игра без жёлтой рамки

Галочка «Без жёлтой рамки» доступна в обоих режимах. В режиме «Только игра» Rewind захватывает выбранное окно через WGC с `display_border=0`; в режиме рабочего стола сохраняется DXGI. При снятой галочке WGC показывает рамку. Выбор окна, отдельный звук игры и поведение при сворачивании сохраняются.

Проверено на этой Windows 11: снимки экрана во время захвата тестового окна подтверждают исчезновение рамки (2914 жёлтых пикселей с рамкой, 81 без неё — фон возле окна). Оба клипа и process audio декодируются, буфер продолжает работать после сохранения. Тест: `Rewind.exe --window-capture-test C:\absolute\test-folder`.

## Версия 0.2.5: DXGI и родной формат аудио

Исправлен запуск режима без жёлтой рамки при изменении разрешения: после масштабирования кадры передаются в NVENC как NV12. Прежний YUV420P воспроизводимо вызывал `CreateInputBuffer failed: invalid param (8)` на RTX 4060 Ti с текущим драйвером и сборкой FFmpeg. Захват в родном разрешении продолжает передавать D3D11-текстуры.

WASAPI открывает физические входы и выходы в их текущем `MixFormat`, без запроса AutoConvertPcm и принудительного формата 48 кГц stereo. Преобразование PCM/float, моно в стерео и пересчёт частоты выполняются внутри Rewind; клипы по-прежнему содержат PCM/AAC 48 кГц stereo. Позиции пакетов рассчитываются по родной частоте устройства, реальные пропуски сохраняются. Process loopback использует отдельный фиксированный формат 48 кГц. Название устройства и формат захвата добавлены в JSON клипа; журнал сохраняет полный хвост ошибок FFmpeg и исключения аудиозахвата.

Проверено на Scarlett 2i2 4th Gen: выход 44,1 кГц stereo float, микрофон 44,1 кГц mono float, DXGI 1080p60 AV1, непрерывный тестовый сигнал до и во время записи, сохранение всех дорожек и декодирование клипа. Формат выхода после остановки не меняется. Программная проверка loopback не подтверждает слышимость сигнала в физических наушниках; этот симптом проверяется пользователем.

Диагностика: `Rewind.exe --borderless-test C:\absolute\test-folder` (короткий тихий тон, захват рабочего стола, WAV/клип/JSON остаются в указанной папке). Сборка в актуальную папку: `./scripts/build.ps1 -OutputDirectory dist/Rewind`.

## Версия 0.2.4: громкость и проверка микрофона

В разделе звука: громкость игры/системы и микрофона 0–100%, программное усиление микрофона 0–30 dB. Настройки сохраняются автоматически; менять их для записи нужно при выключенном буфере. Они применяются к входящему PCM, поэтому действуют и на отдельные дорожки, и на общий Mix. Отдельная дорожка Discord сохраняет исходный уровень. Системные настройки Windows не меняются.

«Проверить микрофон» открывает выбранное устройство без видеобуфера и без записи на диск. В текущей реализации также доступно живое прослушивание через устройство вывода по умолчанию; оно использует отдельный ограниченный буфер и не изменяет production-захват. Уровни peak/RMS после громкости и усиления обновляются каждые 33 мс по последним пакетам WASAPI. Задержка устройства остаётся; длинного усреднения и ожидания клипа нет. Ползунки действуют во время теста, перегрузка отмечается красным; при отсутствии свежих пакетов индикатор сбрасывается. Тест завершается кнопкой, сменой устройства, запуском буфера, закрытием окна или выходом.

Проверено: масштабирование и mute PCM, насыщение без переполнения при усилении, сохранение настроек, запуск настоящего микрофона без видео, отсутствие аудиобуфера в тесте и реакция индикатора на изменение gain.

## Версия 0.2.3: общий буфер после Alt+Tab

Восстановление DXGI теперь перезапускает только видео: аудиозахват продолжает работать, завершённые видеосегменты остаются в общем кольцевом буфере. Автоматические отдельные клипы и уведомления об успешном восстановлении убраны. После трёх неудачных попыток подряд остаётся предупреждение; успешное подключение сбрасывает счётчик.

Хоткей сохраняет один файл из доступных частей до и после переключений. Недоступные интервалы вырезаются из видео и всех аудиодорожек одинаково: на стыке будет скачок, восстановить отсутствующие кадры нельзя. Поэтому длительность клипа может быть короче заданного окна времени. В JSON записывается RemovedCaptureGapSeconds. Хоткей во время переподключения ставит сохранение в ожидание. Лимиты времени и объёма применяются ко всему буферу.

Проверки: два искусственных обрыва DXGI с реальным NVENC, единый клип, декодирование всех дорожек, точное вырезание PCM на стыках и отсутствие автоматических отдельных клипов. Alt+Tab в конкретной игре проверяется пользователем.

## Версия 0.2.2: папка буфера

В настройках можно выбрать «Временные файлы / буфер» на другом диске. Путь сохраняется при включении записи; для изменения нужно остановить буфер. Сегменты видео, временные WAV и сборка MKV пишутся в выбранную папку. При недоступном диске запись не начинается и показывает ошибку; скрытого возврата на C: нет. Старые файлы автоматически не переносятся и не удаляются. По умолчанию прежний путь `%LOCALAPPDATA%/Replay/buffer` сохраняется.

Готовый клип переносится в папку клипов; между дисками сначала копируется во временный файл назначения и только затем публикуется. Сжатие MP4 использует временный файл рядом с итоговым MP4. Настройки, журнал и состояние очереди остаются в `%LOCALAPPDATA%/Replay`; PCM во время захвата хранится в RAM.

## Исправления 0.2.1: восстановление DXGI

- При `DXGI_ERROR_ACCESS_LOST` (`887A0026`), например после перехода в полноэкранную игру, Rewind сохраняет доступные завершённые сегменты и повторно подключает тот же монитор. Максимум три попытки с паузой; после минуты стабильной записи лимит сбрасывается. Автоматической смены режима захвата нет.
- Между сессиями есть разрыв, новый буфер набирается с нуля. Если экспорт старого фрагмента не удался, временная папка сохраняется, её путь виден в интерфейсе. Незавершённый сегмент может быть потерян.
- Интерфейс показывает короткое сообщение, технические подробности остаются в журнале. Проверено искусственным завершением процесса захвата: сохранение старого фрагмента, новый DXGI-буфер и декодирование всех дорожек. Реальный Alt+Tab в конкретной игре требует проверки на месте.

## Исправления 0.1.1

- Аудиозахват работает по событиям WASAPI на отдельном потоке MMCSS, с запасом буфера 100 мс для устройств. PCM-пакеты размещаются по счётчику аудиофреймов; QPC задаёт начальную привязку. Это исключает искусственные щели/наложения из-за колебаний временных меток. Реальные пропуски пакетов не склеиваются; их количество записывается в диагностике.
- Диагностический JSON пишется непосредственно в итоговый файл, без переноса только что созданного файла. Временные sharing violations повторяются с ограниченным ожиданием. Ошибка побочного JSON не объявляет готовое видео несохранённым. Если перенос видео не удался, проверенный MKV сохраняется в staging-папке для восстановления.
- Ошибки экспорта с этапом и путём записываются в `%LOCALAPPDATA%/Replay/errors.log`. Проверки включают искусственную блокировку файлов, PCM с дрожащими метками и непрерывный тон через системный/process loopback.

## Версия 0.2.0: рамка и фоновое сжатие

- «Без жёлтой рамки дисплея (DXGI)» действует в режиме «Игра + рабочий стол». Монитор сопоставляется с конкретным DXGI-адаптером и выходом по HMONITOR; это не скрытый переход к другому монитору. DXGI не создаёт рамку WGC. При отключении галочки используется прежний WGC с рамкой. В режиме «Только игра» рамка остаётся под контролем Windows; скрытие рамки отдельного окна этой версией не реализовано.
- В режиме DXGI запись в родном разрешении передаёт текстуры напрямую в NVENC. При изменении разрешения FFmpeg выполняет масштабирование через CPU: на текущем драйвере `scale_d3d11` не смог выделить текстуру. Поэтому нагрузка в режиме без рамки может отличаться. При сбое DXGI показывается ошибка, незаметного переключения на WGC нет.
- Галочка «Сжимать сохранённые клипы в MP4 в фоне» включает очередь после успешного сохранения. Она доступна во время записи; отключение исключает **новые** задания, а уже поставленные продолжаются. Копия называется `имя.compressed.mp4`, оригинал остаётся. Сжатие не всегда уменьшает уже компактный файл; уведомление сообщает фактический результат.
- Перенесены GPU-пресеты из пользовательского MP4 COMPRESSOR (`constants.py`, `build_compress_command`): p5, CQ 21/27/31/35, H.264/HEVC, ограничение разрешения/FPS. Кнопка импорта читает секцию `compress` из его `settings.json` (или старый плоский формат). Настройки удаления, перезаписи, каталог назначения и выбор единственной аудиодорожки не импортируются. Все AAC-дорожки Rewind копируются без перекодирования, общий микс остаётся первым, имена переносятся в MP4 handler_name. Запуск Python или отдельного окна компрессора не требуется; исходный проект компрессора не меняется.
- Один отдельный процесс сжатия за раз, приоритет CPU ниже обычного, два CPU-потока декодирования/фильтрации. NVENC общий с записью, поэтому нулевое влияние на FPS не гарантируется. Запись и новые сохранения не ждут завершения сжатия.
- Очередь и её последние результаты: `%LOCALAPPDATA%/Replay/compression-queue.json`. При выходе незаконченная обработка прерывается и возобновляется с начала после запуска. Ошибка одного задания не блокирует следующие, оригинал сохраняется. Перед публикацией MP4 проверяются длительность и число аудиодорожек.

## Запуск

`dist/Rewind/Rewind.exe` — автономная сборка, установка .NET не нужна. Держите всю папку вместе.

1. Выберите окно игры (или авто: активируйте игру перед хоткеем).
2. Выберите «Только игра» или «Игра + рабочий стол». Второй режим записывает **весь выбранный монитор**, в том числе другие окна.
3. Выберите звук игры или системы, микрофон и Discord.
4. Включите Rewind. В новой конфигурации Ctrl+Alt+F8 переключает буфер, Ctrl+Alt+F10 сохраняет доступную историю, Ctrl+Alt+F9 переключает обычную запись, Ctrl+Alt+F1 делает снимок экрана. Существующие конфигурации сохраняют прежние назначения; актуальные сочетания видны в разделе «Горячие клавиши» и настраиваются.
5. Закрытие окна сворачивает его в трей. Завершение — «Выход» в меню трея.

Настройки: `%LOCALAPPDATA%/Replay/settings.json`. По умолчанию: 1080p60, 180 секунд, качество CQ 27, максимум 16 Мбит/с. Автовыбор проверяет реальную инициализацию NVENC: AV1 → HEVC → H.264. RTX 2070 Super выбирает HEVC; RTX 4060 Ti может использовать AV1.

Клип — MKV с первой дорожкой Mix и отдельными Game/System, Microphone, Discord. Системная дорожка уже содержит Discord; при создании Mix он повторно не добавляется. Рядом JSON с RMS/peak, длительностью тишины и предупреждениями. Неисправный/тихий микрофон не блокирует сохранение видео. Звук успеха и уведомление появляются после проверки файла через ffprobe и успешной публикации оригинального MKV. Миниатюра создаётся асинхронно; необязательное MP4-сжатие выполняется в фоне и не является условием успеха сохранения.

## Сборка и проверка

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1 -Test
```

SDK устанавливается только в `.tools`, системная установка не меняется. Тест проверяет PCM, тишину, обрезку, запись окна, NVENC, системное и процессное аудио, сохранение при активном буфере, повторное сохранение и декодирование дорожек. Во время интеграционного теста появляются тестовое окно и короткая запись выбранного основного монитора; результаты остаются локально в `artifacts/self-test`.

Отдельная аппаратная проверка AV1-экспорта: `./scripts/test-nvdec-export.ps1`. Нужны открытый рабочий стол Windows и NVIDIA с AV1 decode/encode; закройте обычный Rewind перед запуском. Тест создаёт небольшое анимированное окно и захватывает основной монитор. Он сравнивает кадры/PTS и аудиосэмплы NVDEC и software из одного снимка, проверяет второй Save через 15 секунд, software fallback, rollback, recovery и обычную запись одновременно с Rewind. Настройки пользователя и очередь сжатия не перезаписываются; пользовательские задания не запускаются. Тестовые медиа и отчёт остаются в `artifacts/nvdec-export-test`.

Проверка packet-copy и его границ: `./scripts/test-packet-copy.ps1` с теми же аппаратными требованиями. Реальные AV1 fixtures проверяют пакеты, кадры/PTS, все аудиодорожки, несовместимые headers/форматы, gaps, fallback, rollback, file locks и повторный Save при активной обычной записи. Результаты остаются в `artifacts/packet-copy-test`.

`bootstrap.ps1` фиксирует SDK 10.0.401, а `Replay.csproj` — NAudio.Wasapi 2.3.0 (NAudio.Core 2.3.0 транзитивно). FFmpeg загружается по изменяемому URL latest release без version/hash lock; побайтовая воспроизводимость сборки пока не обеспечена. `.tools`, `bin`, `obj`, `dist`, `publish` и `artifacts` не входят в Git; исходники тестов и необходимые шрифты/иконки остаются trackable.

## Устройство и ограничения первой версии

- FFmpeg — отдельный процесс. WGC использует D3D11/NVENC; DXGI в родном разрешении также передаёт GPU-текстуры, а существующий путь масштабирования DXGI использует CPU и NV12. Аудио WASAPI записывается приложением по QPC-меткам и кодируется в AAC при сохранении.
- Видео хранится во временных двухсекундных MKV-сегментах. Ограничения по времени и размеру; аудио Rewind — ограниченный RAM-буфер PCM16 48 кГц stereo (около 35 МБ на дорожку за 3 минуты). При сохранении сегменты защищены от очистки. После нормальной очистки завершённой сессии временные данные удаляются; данные незавершённой обычной записи сохраняются вместе с журналом и PCM на диске. При запуске такие сессии обнаруживаются и показывается предупреждение, без автоматического удаления; восстановление реализовано как внутренний/ручной путь. Аудио, существовавшее только в RAM-буфере Rewind, после аварии не восстанавливается.
- Временная привязка видео оценивается по прибытию кадров до кодирования; WASAPI использует системный QPC. Для точной подстройки доступен сдвиг аудио. Это ещё не гарантированная покадровая синхронизация; нужна проверка на конкретной игре/устройствах.
- Save Rewind фиксирует границу по QPC при принятии команды, ждёт закрытия содержащего её сегмента (обычно до 2 секунд, deadline 4 секунды), не останавливая общий захват. Начало ограничено настроенной длительностью, включением Rewind и границей предыдущего успешного Save. При непригодных для packet-copy границах видео декодируется, обрезается через `trim/setpts` на сетке доступных кадров и полностью перекодируется в NVENC; это не stream-copy и не округление начала к предшествующему ключевому кадру. PCM обрезается по тем же интервалам, а недоступные интервалы удаляются из видео и аудио одинаково. При буфере 30 секунд и втором Save через 15 секунд после первого второй клип содержит только новую историю, примерно 15 секунд. Cutoff устанавливается после закрепления сегментов и PCM snapshot; при неуспешном экспорте предусмотрен rollback с проверкой epoch. Обычная запись владеет своими сегментами/PCM и не сбрасывается сохранением Rewind. Финализация использует дополнительную NVENC-сессию и может быть существенно дольше ожидания сегмента.
- Только SDR. HDR не проходит корректный tone mapping в этой версии. Разрешение — холст 16:9, исходные пропорции сохраняются с полями.
- AV1 Save Rewind использует `av1_cuvid`/CUDA до NVENC, если конкретный формат закрытого сегмента прошёл реальную аппаратную decode-проверку. Результат capability-проверки кешируется; при недоступности NVDEC остаётся прежний software decoder. При ошибке аппаратного экспорта его неопубликованный результат удаляется, а тот же закреплённый снимок сегментов и PCM экспортируется software-путём без нового Save/cutoff. На decoded-пути видео полностью перекодируется, дополнительная NVENC-сессия остаётся. Обычная запись, H.264/HEVC, bundled FFmpeg и формат настроек не меняются.
- Исключение для безопасного AV1 packet-copy: начало каждого диапазона совпадает с началом закрытого сегмента, sequence headers/формат/цвет/timebase совместимы, битстрим содержит только показанные low-delay KEY/INTER frames без hidden/show-existing/layers, а пакетная временная сетка точно совпадает с decoded-trim. Не округляет cutoff к предыдущему keyframe. После copy проверяются хэши/PTS каждого пакета и полное декодирование всех дорожек с точным числом кадров; только затем публикуется MKV. Аудио обрабатывается как прежде. При неопределённости или отказе copy используется тот же снимок через NVDEC/software; дополнительный NVENC остаётся только у decoded экспорта. Это консервативный fast path для совместимых AV1 Main 4:2:0 8/10-bit Matroska; Hybrid SaveClip реализован отдельно и выключен по умолчанию до подтверждения полезной production latency. Его direct NVDEC/NVENC boundary, exact copy и полная проверка source/output video/AAC описаны в dev/HybridExportChecks/README.md; пользовательских настроек активации нет.
- При свёрнутой игре Windows может перестать отдавать кадры: приложение показывает предупреждение, изображение может замереть. Автоматического перехода к рабочему столу нет. Защищённый контент и отдельные fullscreen-режимы требуют проверки.
- Автоисточник — эвристика последнего активного приложения. Для надёжности выберите окно игры явно; название папки можно сохранить для exe. В течение записи источник и имя не меняются при Alt+Tab.
- Discord должен быть запущен до начала записи. При его перезапуске или отключении аудиоустройства перезапустите буфер. Автопереподключение ещё не реализовано. Устройство по умолчанию фиксируется на старте сессии.
- При потере DXGI видеозахват переподключается с ограниченными попытками; завершённая Rewind-история и аудиозахват сохраняются, а разрывы отражаются в метаданных. Активная обычная запись завершается до восстановления. Нет автозапуска с Windows или автозаписи при запуске игры.
- Успешное сохранение показывает собственный оверлей Rewind. Его видимость поверх конкретного эксклюзивного fullscreen-режима требует проверки; системные уведомления Windows также могут подавляться игровым режимом. Состояние и ошибки остаются в окне и трее.
